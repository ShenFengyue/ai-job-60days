# Day 55 / 60：System Design——设计 AI 客服与研究助手

**日期：2026 年 11 月 13 日。**

今天练习系统设计面试。目标不是画复杂架构，而是从需求、约束和失败模式推导最小可靠系统。

## 1. 今日目标

分别设计 AI 客服与 AI 研究助手，写出需求、数据流、容量假设、可靠性、安全、成本与演进方案。

## 2. 设计方法

依次回答：谁使用？最重要任务是什么？功能与非功能需求是什么？请求量、并发、延迟、可用性和数据规模如何假设？哪些数据持久化、谁能访问？主链路如何工作？哪些地方会失败？如何监控质量、成本和安全？什么规模下才需要扩展？

不要一开始就选 Kafka、Kubernetes 或微服务。先找到真正的瓶颈。

## 3. 设计 A：AI 客服

参考架构：

```text
Web → API/Auth/Rate Limit → Conversation Service
                          → Knowledge Retrieval → LLM
                          → Response Validator
                          → Human Handoff
             ↓
       DB / Logs / Metrics / Traces
```

关键问题：客户身份与租户隔离；知识库权限；人工转接；退款、改订单等副作用工具审批；高峰排队；模型不可用时降级到人工客服。

## 4. 设计 B：AI 研究助手

```text
Upload → Object Storage → Parse Queue → Chunk/Embed → Vector Index

Question → API → Permission Filter → Retrieve → Rerank
         → LLM → Citation Check → Answer
```

关键问题：大文件异步处理；文档版本；删除文档时索引同步删除；来源引用；长文档成本；多租户隔离；检索评估与答案回归。

## 5. 可靠性设计

对每个外部依赖考虑 Timeout、Retry、Idempotency、Fallback、Recovery、Fault Isolation。重试只用于适合重试的错误，并限制次数、采用退避；有副作用的操作使用幂等键。队列任务需要重试上限、死信处理和可观测状态。

模型调用设置 token/context 上限、请求预算和并发控制。
