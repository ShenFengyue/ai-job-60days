# Day 40 / 60：GitHub Actions 自动构建与发布 Docker 镜像

**日期：2026 年 10 月 29 日。**

本地容器能运行后，把构建流程放进 GitHub Actions：Pull Request 自动验证镜像能否构建；主分支更新后发布到 GitHub Container Registry（GHCR）。

## 1. 今日目标

理解 CI（自动验证）与 CD（交付发布）的区别，并建立最小镜像流水线。

```text
Pull Request → checkout → build image → 验证
main push → checkout → build → 登录 GHCR → push image
```

## 2. 学习材料

- [GitHub: Publishing Docker Images](https://docs.github.com/en/actions/tutorials/publishing-packages/publishing-docker-images)
- [Docker Build Push Action](https://github.com/docker/build-push-action)
- [Docker GitHub Actions](https://docs.docker.com/build/ci/github-actions/)

使用前检查官方文档当前推荐的 action 版本，不要把旧教程的版本号当永久不变。

## 3. Coding Practice

创建 `.github/workflows/publish-image.yml`。以下是结构示例，正式使用前按默认分支和当前 action 版本校验：

```yaml
name: Build and publish image

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read
  packages: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - name: Build image
        uses: docker/build-push-action@v6
        with:
          context: .
          push: ${{ github.event_name == 'push' && github.ref == 'refs/heads/main' }}
          tags: ghcr.io/${{ github.repository }}:${{ github.sha }}
```

这是入门骨架。正式发布需要配置 GHCR 登录、确认仓库命名与权限，并让 PR 只 build、不 push；只有主分支可信提交才获得发布凭证。实际 workflow 应按官方当前示例补齐登录步骤和权限边界。

镜像使用 commit SHA 标签，避免只依赖 latest。这样每个镜像都能追溯到源代码版本。

## 4. 验证

1. 创建分支并提交 workflow。
2. 发起 PR，确认构建执行但不发布。
3. 合并到主分支，确认 GHCR 出现镜像。
4. 检查 tag 与 commit SHA 一致。
5. 拉取镜像并运行健康检查。
6. 查看 Actions 日志，确认没有输出密钥。

## 5. 安全边界

使用最小权限；不要在 workflow 写个人访问令牌；不要让 fork PR 获得发布凭证；定期更新 action，高安全要求可固定完整 commit SHA；不要把 latest 当唯一版本标识。

## 6. Deliverable

提交 `.github/workflows/publish-image.yml` 与 README。README 写明触发条件、镜像地址、标签策略、权限和回滚方式。

```bash
git add .github/workflows/publish-image.yml README.md
git commit -m "Day 40: automate Docker image build and publish"
git push
```

验收：PR 触发构建但不发布；主分支 push 能发布镜像；镜像 tag 可追溯；镜像可运行；没有硬编码密钥。

**面试题：** 为什么不能只用 latest？为什么 PR 构建和正式发布应分开控制权限？
