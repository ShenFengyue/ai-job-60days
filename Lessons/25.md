## 1. 今日学习目标

今天只做一件事：**让昨天的 FastAPI 服务在 Docker 容器中成功运行。**

先理解三个概念：

| 概念              | 你可以怎么理解                       |
| ----------------- | ------------------------------------ |
| Dockerfile        | 一份说明书，告诉 Docker 如何打包程序 |
| Image（镜像）     | 打包完成的应用运行模板               |
| Container（容器） | 镜像启动后运行的实例                 |

整体流程：

```
你的 Python 项目
      ↓
  Dockerfile
      ↓
  Docker Build
      ↓
  Docker Image
      ↓
  Docker Run
      ↓
  运行中的容器
      ↓
  http://localhost:8000/docs
```

今天不学 Kubernetes，不配置云服务器，也不部署复杂的多容器系统。

[Docker Python 官方指南](https://docs.docker.com/guides/python/?utm_source=chatgpt.com)

**今天的主材料。** 它直接展示如何将 Python 应用封装为容器，包括 Dockerfile、依赖安装和 Compose。

重点理解：为什么要先安装依赖，再复制应用代码，以及怎样利用 Docker 构建缓存提高效率。

### ② Docker 官方：编写 Dockerfile

[Writing a Dockerfile](https://docs.docker.com/get-started/docker-concepts/building-images/writing-a-dockerfile?utm_source=chatgpt.com)

重点理解 6 个指令：

- `FROM`：选择基础镜像。
- `WORKDIR`：设置工作目录。
- `COPY`：复制文件。
- `RUN`：在构建过程中执行命令。
- `EXPOSE`：声明应用使用的端口。
- `CMD`：指定容器启动时执行的命令。

特别留意官方示例中的非 root 用户设置。即使是个人项目，也值得养成基本的安全习惯。

## 3. 必须完成的 Coding Practice

### 第一步：确认 Docker 可以使用

如果你使用 Windows，先检查是否已经安装并启动 Docker Desktop。

打开终端，执行：

```
docker --version
docker info
```

第一条查看版本，第二条检查 Docker 引擎是否正常运行。

如果 Docker Desktop 尚未安装，按照 [Docker 官方安装指南](https://docs.docker.com/desktop/setup/install/windows-install/?utm_source=chatgpt.com) 完成安装。

**不要在 Docker 尚未正常运行时继续写 Dockerfile。**

### 第二步：检查项目结构

进入昨天的 `rag-agent` 项目，确认至少存在：

```
rag-agent/
├── app.py
├── agent.py
├── schemas.py
├── requirements.txt
├── .env
└── .gitignore
```

这里假设 FastAPI 对象定义为 `app.py` 中的 `app`。

如果你的文件名不同，后面的命令需要对应修改。

### 第三步：创建 Dockerfile

在项目根目录新建一个文件，名字就叫：

```
Dockerfile
```

注意：**不要添加 `.txt` 扩展名。**

写入：

```
FROM python:3.12-slim

WORKDIR /app

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

RUN useradd --create-home appuser

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY . .

RUN chown -R appuser:appuser /app

USER appuser

EXPOSE 8000

CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

这是一个用于学习的基础版本。

你需要理解它的运行逻辑：

1. 选择 Python 运行环境。
2. 创建应用工作目录。
3. 安装项目依赖。
4. 复制项目文件。
5. 使用非 root 用户运行应用。
6. 启动 FastAPI 服务。

这里使用 Python 3.12，是为了给当前项目提供相对保守的兼容性起点，不代表它是最新 Python 版本。实际项目应根据依赖兼容性选择版本，并在正式发布时进一步固定基础镜像版本。

### 第四步：创建 `.dockerignore`

在同一目录下创建：

```
.dockerignore
```

写入：

```
.venv/
venv/
__pycache__/
.pytest_cache/
.git/
.env
*.pyc
```

它告诉 Docker：构建镜像时，不要把这些文件发送进构建上下文。

其中最重要的是：

**`.env` 不应进入镜像，因为里面可能保存 API 密钥。**

### 第五步：构建镜像

在项目根目录运行：

```
docker build -t rag-agent:day25 .
```

注意命令最后的 `.`，它表示使用当前目录作为构建上下文。

构建成功后，运行：

```
docker images
```

你应该能看到 `rag-agent` 镜像。

如果构建失败，先查看报错位置。常见问题包括依赖没有写进 `requirements.txt`、文件名不匹配，或者依赖不支持当前 Python 版本。

### 第六步：启动容器

如果你的项目需要 API 密钥，可以通过环境文件传入：

```
docker run -d --name rag-agent-api --env-file .env -p 8000:8000 rag-agent:day25
```

这条命令的意思是：

- `-d`：在后台运行。
- `--name`：给容器命名。
- `--env-file .env`：从本地环境文件读取环境变量。
- `-p 8000:8000`：将电脑的 8000 端口映射到容器的 8000 端口。

注意：`.env` 只在运行时传入，并没有被打包进镜像。不要把它提交到 GitHub。

如果暂时没有 `.env`，并且应用启动不依赖必需的环境变量，可以先去掉 `--env-file .env` 运行；否则请按项目实际需要配置。

### 第七步：验证服务

打开浏览器：

```
http://localhost:8000/docs
```

如果能够看到昨天创建的 FastAPI 接口文档，说明容器中的服务已经运行。

再检查健康接口：

```
http://localhost:8000/health
```

预期返回：

```
{
  "status": "ok"
}
```

最后查看容器日志：

```
docker logs rag-agent-api
```

如果无法访问服务，先执行：

```
docker ps -a
```

检查容器是否仍在运行。如果已经退出，再通过 `docker logs rag-agent-api` 定位问题。

测试完成后，可以停止并删除容器：

```
docker rm -f rag-agent-api
```

这不会删除你构建的镜像。

### 两道面试题

**Q1：Docker Image 和 Container 有什么区别？**

答题思路：Image 是包含应用及其运行所需文件的模板；Container 是基于镜像创建的运行实例。同一个镜像可以启动多个容器。

**Q2：为什么不直接把 API Key 写进 Dockerfile？**

答题思路：Dockerfile 中写入的密钥可能留在镜像层、构建缓存或镜像分发过程中。应该通过运行时环境变量或专门的密钥管理机制注入，并避免将密钥提交到代码仓库。
