# 1）今日学习目标

今天只解决一个问题：

> **普通 RAG 和 Agentic RAG 到底有什么区别？**

普通 RAG：

```
User Question
      ↓
Retriever
      ↓
Top-K Documents
      ↓
LLM
      ↓
Answer
```

Agentic RAG：

```
User Question
      ↓
     Agent
      ↓
需要知识库？
 ┌────┴────┐
No         Yes
 ↓          ↓
直接回答   search_knowledge
              ↓
          Retrieved Docs
              ↓
             Agent
              ↓
       还需要其他 Tool？
          ↓        ↓
        Yes        No
          ↓        ↓
        Tool     Answer
```

也就是说：

> **RAG 不再是固定流水线，而变成 Agent 可以调用的工具。**

Hugging Face 官方材料正是这么定义 Agentic RAG 的：Agent 可以根据问题动态决定使用 RAG 或其他工具，而不是每次都强制执行一次固定检索。[Hugging Face](https://huggingface.co/learn/agents-course/unit3/agentic-rag/agentic-rag?utm_source=chatgpt.com)

# 5）第一步：把你原来的 RAG 包成 Tool

核心结构：

```
from smolagents import tool


@tool
def search_knowledge(query: str) -> str:
    """
    Search the internal knowledge base and return relevant information.

    Args:
        query: The user's information need.
    """

    results = retrieve_documents(query)

    return "\n\n".join(results)
```

你原来的：

```
query
 ↓
embedding
 ↓
vector search
 ↓
top-k
 ↓
context
```

全部保留。

只是现在：

```
RAG Pipeline
     ↓
Python Function
     ↓
@tool
     ↓
Agent Tool
```

# 今日面试题

### ① 普通 RAG 和 Agentic RAG 最大区别？

一句话：

> **普通 RAG 是固定检索流程；Agentic RAG 让 Agent 把检索作为一种可选择、可重复执行的行动。**

------

### ② Agentic RAG 有什么代价？

至少答三个：

```
1. 更多 LLM calls
2. 更高 latency
3. 更高 API cost
4. 更难 debug
5. Agent 可能不必要地调用 retrieval
```

所以：

> **不是所有 RAG 都应该 Agentic 化。**

这也是一个很好的工程面试回答。
