# Day 56 / 60：Project Storytelling——把项目讲成可信的工程经历

**日期：2026 年 11 月 14 日。**

面试官不只想知道用了什么技术，更想知道你解决了什么问题、为什么这样设计、遇到什么失败、如何验证结果。今天为三个项目准备不同长度的讲述版本。

## 1. 今日目标

每个项目分别准备 90 秒、5 分钟和 15 分钟版本。所有数字、功能和贡献必须真实可核实。

## 2. 讲述结构

1. Problem：用户遇到什么问题？
2. Context：原来方案有什么限制？
3. Decision：你做了什么设计选择？为什么？
4. Implementation：关键链路由哪些组件组成？
5. Evidence：如何测试、评估和部署？
6. Trade-off：付出了什么成本？有哪些限制？
7. Learning：如果重做，会改什么？

不要把技术名词当成果。“使用向量数据库”不如解释它解决了哪种检索问题，以及如何验证检索质量。

## 3. 三个项目的讲述重点

- ResearchAI：文档解析、chunking、检索、reranking、引用与检索评估。
- Research Agent：工具选择、执行循环、状态、失败恢复、安全权限与任务评估。
- XiaoYa 2.0：产品场景、用户体验、记忆与检索、后端架构、隐私和风险控制。

明确区分自己完成、AI 辅助、第三方服务提供的部分。不要把调用第三方 API 描述成训练了模型。

## 4. 练习

录音或录屏回答：90 秒讲清价值；5 分钟讲架构和一项关键决策；15 分钟接受数据、失败、成本、安全、评估方面的追问。

回放时检查是否出现“高效”“智能”“先进”等空泛词，并用具体证据替换。让听众复述项目解决的问题，检验表达是否清楚。

## 5. 项目追问清单

每个项目准备回答：为什么选择这个架构？你亲自写了哪些部分？最难的 bug 是什么？如何评估正确性？失败时用户看到什么？成本来自哪里？如何保护数据？请求量增长 10 倍哪里先成为瓶颈？

## 6. Deliverable

创建 `job-search/project-stories.md`，为三个项目写 90 秒、5 分钟、15 分钟版本，并附 8 个追问答案。

```bash
git add job-search/project-stories.md
git commit -m "Day 56: prepare AI project interview stories"
git push
```

验收：每个版本接近目标时长；内容有项目证据；能区分个人贡献、第三方能力与未实现功能。

**提醒：** 诚实讲清一个扎实的小项目，胜过夸大一个自己无法解释的大项目。
