# Day 38 / 60：Docker 容器化 RAG API

**日期：2026 年 10 月 27 日。**

今天把 Python API 打包成 Docker 镜像，让它在不同电脑和服务器上拥有更一致的运行环境。

## 1. 今日目标

创建 Dockerfile、构建镜像、运行容器，并从宿主机访问 API。理解 Image 与 Container：镜像是只读模板，容器是镜像运行后的隔离进程环境。

## 2. 学习材料

- [Docker Get Started](https://docs.docker.com/get-started/)
- [Dockerfile Reference](https://docs.docker.com/reference/dockerfile/)
- [Docker Python Guide](https://docs.docker.com/guides/python/)

先完成一个服务的容器化，不必先学 Kubernetes。

## 3. Coding Practice

在项目根目录创建 Dockerfile：

```dockerfile
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

假设入口是 `main.py`、FastAPI 对象叫 `app`；否则按实际项目调整 CMD。生产项目应固定验证过的基础镜像版本，考虑非 root 用户和依赖锁定。

创建 `.dockerignore`：

```text
.venv
__pycache__
.git
.env
.pytest_cache
*.pyc
```

构建与运行：

```bash
docker build -t rag-api:day38 .
docker run --rm -p 8000:8000 --env-file .env rag-api:day38
```

访问 `http://localhost:8000/docs` 和健康检查接口。容器内的 localhost 指向容器自身，不是宿主机；外部数据库要使用可达的网络地址。

## 4. 密钥与数据

不要把 .env 复制进镜像，不要在 Dockerfile 写真实 API Key。通过运行时环境变量或 secrets 注入。需要持久化的数据放 volume 或外部数据库，不要假设容器文件系统永久保存。

## 5. 验证与交付

验证镜像构建、容器启动、API 可访问、RAG 核心请求成功、停止后可重新启动，并确认密钥未进入镜像层。

提交 Dockerfile、.dockerignore、README：

```bash
git add Dockerfile .dockerignore README.md
git commit -m "Day 38: containerize RAG API with Docker"
git push
```

验收：他人能按 README 从零构建运行；健康检查成功；密钥不在仓库和镜像中；数据持久化策略清楚。
