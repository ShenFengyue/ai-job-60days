# Day 50 / 60：Portfolio Release——正式发布三个 AI 项目

**日期：2026 年 11 月 8 日。**

今天不是再加功能，而是完成一次可交付发布。目标是把 ResearchAI、Research Agent 和 XiaoYa 2.0 作为三个有边界、有演示、有证据的作品公开呈现。

## 1. 今日目标

为每个项目打一个可追踪版本，确认 Demo、README、架构图、测试与限制说明一致，并建立一个作品集入口页。

## 2. Release Gate

每个项目发布前检查：

- 核心用户路径可以真实运行。
- Demo 链接可访问，或提供清晰的本地运行方式。
- README 的安装步骤在干净环境验证过。
- API Key、数据库密码、用户数据没有进入仓库。
- 自动化测试与必要评估通过。
- 依赖与部署配置可复现。
- 已知限制、失败模式和成本假设已写明。
- 发布版本与 commit SHA 可追溯。

## 3. 版本与发布

按项目采用 SemVer（如适用）：MAJOR 表示不兼容变更，MINOR 表示向后兼容功能，PATCH 表示兼容修复。个人项目可以用 v1.0.0 作为首次稳定发布标记，但不要仅因为有 tag 就宣称生产级。

```bash
git status
git tag -a v1.0.0 -m "ResearchAI v1.0.0"
git push origin v1.0.0
```

按项目分别发布，不要把同一个 tag 命令机械复制到所有仓库。若功能尚未稳定，使用 v0.x 并明确状态。

## 4. 作品集入口

建立一个简洁 Portfolio README 或个人主页。每个项目只回答五个问题：

1. 它解决什么问题？
2. 谁会使用？
3. 关键技术链路是什么？
4. 你亲自实现了什么？
5. 如何验证它确实有效？

项目顺序按证据强度和目标岗位相关性排序，不按代码量排序。

## 5. Demo 录制

每个项目录制 1–3 分钟真实演示：展示输入、核心过程、输出、来源或评估结果。不要只录启动动画；不要隐藏失败状态；不要展示真实 API Key 或隐私数据。

## 6. Deliverable

- 三个项目的发布说明与 tag（仅对达到发布门槛的项目）。
- 一个作品集入口 README。
- 三个真实 Demo 或截图。
- 一份发布前检查记录。

```bash
git add README.md
git commit -m "Day 50: publish AI engineering portfolio"
git push
```

验收：至少两个项目有可访问 Demo；三个项目的功能与限制可解释；所有发布内容可追溯；没有虚假能力描述。
