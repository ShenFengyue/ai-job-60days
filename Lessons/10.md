## Day 10｜文本切分（Chunking）：把原始文档变成可检索的知识单元

今天是 **Day 10（2026 年 9 月 14 日）**。昨天你已经完成了 FAISS 向量索引，今天进入 RAG 的关键前置步骤：

> **先把长文档切成合适大小的 chunks，再做 embedding 和检索。**

如果切分太大，检索结果会混入大量无关内容；如果切分太小，语义会被切碎，模型拿到的上下文不完整。今天先不接 LLM 问答，只把“文档 → chunks → embedding → 检索”做稳。

------

## 1）今日学习目标

今天完成后，你应该能：

- 解释为什么长文档不能直接作为一个整体做 embedding；
- 实现至少两种切分方法：
  - 固定字符长度切分；
  - 按段落切分；
- 理解 `chunk_size`、`chunk_overlap` 的作用；
- 为每个 chunk 保存来源、序号和原文位置等 metadata；
- 比较不同切分策略对检索结果的影响；
- 认识到 chunking 不是“越细越好”，而是检索质量与上下文完整性的平衡。

今天的核心链路：

```
原始文档
→ 清洗
→ 切分 chunks
→ 保存 metadata
→ embedding
→ 向量检索
```

Hugging Face 的官方课程在处理长文本时，明确采用“将文本拆成多个 chunks，而不是简单截断”，并通过 overflow 机制保留完整内容；这正是今天要建立的基础思路。[Hugging Face](https://huggingface.co/docs/course/chapter7/6?utm_source=chatgpt.com)

### 第二步：实现 3 种切分策略

`main.py` 至少实现以下函数：

```
from pathlib import Path


def load_document(path: str) -> str:
    return Path(path).read_text(encoding="utf-8")


def split_by_paragraph(text: str) -> list[str]:
    return [
        block.strip()
        for block in text.split("\n\n")
        if block.strip()
    ]


def split_by_fixed_size(
    text: str,
    chunk_size: int = 300,
    overlap: int = 50,
) -> list[str]:
    if overlap >= chunk_size:
        raise ValueError("overlap 必须小于 chunk_size")

    chunks = []
    start = 0

    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end].strip()

        if chunk:
            chunks.append(chunk)

        start += chunk_size - overlap

    return chunks


def split_by_sentences(
    text: str,
    max_chars: int = 300,
) -> list[str]:
    sentences = text.replace("。", "。\n").splitlines()

    chunks = []
    current = ""

    for sentence in sentences:
        sentence = sentence.strip()
        if not sentence:
            continue

        if len(current) + len(sentence) <= max_chars:
            current += sentence
        else:
            if current:
                chunks.append(current)
            current = sentence

    if current:
        chunks.append(current)

    return chunks
```

今天不要求使用复杂的 LangChain splitter。你需要先亲手理解切分机制，再决定是否引入框架。

### 第三步：为每个 chunk 加 metadata

每个 chunk 至少保存：

```
def build_chunk_records(chunks: list[str], strategy: str) -> list[dict]:
    records = []

    for index, chunk in enumerate(chunks):
        records.append(
            {
                "chunk_id": f"{strategy}-{index}",
                "strategy": strategy,
                "chunk_index": index,
                "text": chunk,
                "char_count": len(chunk),
            }
        )

    return records
```

最终 `chunks.json` 建议包含：

```
[
  {
    "chunk_id": "fixed-0",
    "strategy": "fixed",
    "chunk_index": 0,
    "text": "...",
    "char_count": 287
  }
]
```

### 第四步：把三种切分策略接入 Day 9 的 FAISS 检索

你需要复用昨天的 embedding + FAISS 代码，对三种策略分别建立索引：

- `paragraph`
- `fixed_300_overlap_50`
- `sentence_300`

查询至少使用这 4 个问题：

```
What is the main purpose of this document?
What does it say about AI learning?
What practical steps are recommended?
Which part is most relevant to a beginner?
```

对每种切分策略分别返回 top-3 结果。

`results.json` 建议结构：

```
[
  {
    "strategy": "fixed_300_overlap_50",
    "query": "What practical steps are recommended?",
    "matches": [
      {
        "chunk_id": "fixed-2",
        "score": 0.8123,
        "text": "..."
      }
    ]
  }
]
```

你今天真正要比较的不是“哪个分数最高”，而是：

- 返回的 chunk 是否完整；
- 是否包含回答问题所需的信息；
- 是否出现大量无关上下文；
- 同一个事实是否被切到两个 chunk 中；
- overlap 是否减少了信息断裂。

------

### 第五步：做一个简单的人工评估

建立一个小评分表，每个 query、每种策略打 0–2 分：

- **相关性**：返回内容是否与问题直接相关；
- **完整性**：是否包含回答问题所需的完整信息；
- **噪音**：是否混入大量无关内容；
- **边界质量**：句子或段落是否被粗暴切断。

总分示例：

```
每个 query 最高 8 分
4 个 query 最高 32 分
```

你不需要追求科学论文级评测，但必须有固定规则，不能只凭“看起来不错”。

你的最终通过标准是：

> 给定一份长文档，你能自己设计切分方式、保留来源信息，并用固定查询验证切分质量。
