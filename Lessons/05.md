## Day 5｜Prompt 设计：把“会问 AI”变成“会设计可重复的任务”

今天是 **Day 5（2026 年 9 月 9 日）**。你已经完成了 Python、API、Git、LLM 请求/响应的基础，今天进入真正的应用开发核心：**如何把一个模糊需求写成模型更容易稳定执行的任务**。

今天不追求“神奇 Prompt”，而是训练一种工程能力：

```
模糊需求
→ 明确任务
→ 写清约束
→ 指定输出格式
→ 用固定测试集比较
→ 保留更好的版本
```

这正是后面做结构化输出、RAG、Agent 和 XiaoYa 时会反复使用的工作方式。

### 1）今日学习目标

今天完成后，你应该能：

- 把一个模糊请求拆成：任务、背景、输入、约束、输出格式；
- 判断什么时候需要示例，什么时候不需要；
- 为同一个任务写出多个 Prompt 版本；
- 用固定测试集比较不同 Prompt，而不是凭感觉判断；
- 发现 Prompt 问题到底来自指令不清、上下文不足，还是模型能力限制；
- 让模型输出更稳定、更容易被程序读取的结果。

今天只掌握一个核心公式：

```
高质量 Prompt
= 任务目标
+ 必要背景
+ 明确约束
+ 输出契约
+ 测试与比较
```

### 2）今天最值得看的 4 个材料

**材料 1：Anthropic 官方 Prompt Engineering Overview**
这是今天最值得精读的主材料。重点看它对“定义成功标准、建立测试方法、判断是否真的适合用 Prompt 解决”的说明。它的价值不只是教你写提示词，而是把 Prompt 当成一个需要验证的工程对象。[Anthropic Prompt Engineering Overview](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview?utm_source=chatgpt.com)

**材料 3：Hugging Face Context Course 导论**
这不是今天要完整学完的课程，而是用来建立一个更先进的认识：未来的重点不只是“写一句更聪明的话”，而是组织模型在正确时间拿到正确知识。它的课程结构包含可运行代码、项目和小测，适合你在后续 RAG、Agent 阶段再深入。今天只看导论，避免过早堆课程。[Hugging Face](https://huggingface.co/learn/context-course/unit0/introduction?utm_source=chatgpt.com)

**材料 4：你在 Day 4 写的 CLI Chat**
这是最重要的实践材料。不要另起炉灶，直接在已有程序上做 Prompt A/B 测试。因为你的目标不是背理论，而是看到：**Prompt 改了一处，模型行为具体发生了什么变化。**

### 3）必须完成的 coding practice

今天在本地创建：

```
exercises/day05-prompt/
├── main.py
├── test_cases.json
├── results.json
└── README.md
```

你要做一个“小型英文学习任务评测器”。

程序输入一个英文单词，要求模型返回：

```
{
  "word": "abandon",
  "meaning": "放弃；遗弃",
  "example": "He decided to abandon the plan.",
  "mnemonic": "..."
}
```

今天不要求你解决严格 JSON 解析问题，那是 Day 6 的重点；今天先专注于 Prompt 设计和比较。

#### 第一步：准备固定测试集

`test_cases.json`：

```
[
  {"word": "abandon"},
  {"word": "subtle"},
  {"word": "resilient"},
  {"word": "ambiguous"},
  {"word": "allocate"},
  {"word": "contemplate"},
  {"word": "inevitable"},
  {"word": "coherent"},
  {"word": "bias"},
  {"word": "retrieve"}
]
```

#### 第二步：写 3 个 Prompt 版本

**Prompt A：模糊版**

```
请解释这个单词：{word}
```

**Prompt B：约束版**

```
请解释英文单词“{word}”。

要求：
1. 给出简短中文释义；
2. 给出一个自然英文例句；
3. 给出一个适合中国学习者的记忆方法；
4. 不要输出无关内容。
```

**Prompt C：输出契约版**

```
你是一个英语词汇教师。

任务：解释单词“{word}”。

要求：
- meaning：给出 1–2 个最常用的中文释义；
- example：给出一个自然、难度适中的英文例句；
- mnemonic：给出一个简短、容易记住的联想；
- 不要编造词源；
- 不要添加标题、开场白或结尾客套话；
- 按以下顺序输出：
meaning:
example:
mnemonic:
```

#### 第三步：批量运行并保存结果

你的 `main.py` 至少完成这些事情：

1. 读取 `test_cases.json`；
2. 依次运行 Prompt A、B、C；
3. 对每个单词保存模型输出；
4. 将结果写入 `results.json`；
5. 在终端打印每个 Prompt 版本的结果。

你可以沿用 Day 4 的 API 调用函数，但把它整理成：

```
def call_llm(prompt: str) -> str:
    ...
```

再写：

```
def build_prompt(version: str, word: str) -> str:
    ...
```

这一步非常重要，因为你正在从“手写一段程序”过渡到“把 Prompt 当作可测试组件”。

#### 第四步：人工评估

给每个输出打分，每项 0 或 1：

- 是否真的解释了目标单词；
- 中文释义是否准确；
- 例句是否自然；
- 记忆法是否有帮助；
- 是否遵守了输出限制。

总分：

```
每条结果最高 5 分
10 个单词最高 50 分
```

在 `README.md` 写出三种 Prompt 的总分和你的结论。

### 5）今天的验收标准

今天通过，不是因为你看完了几篇文章，而是因为你能完成下面这些事情：

- 用自己的话解释“任务目标”和“输出契约”的区别；
- 说出 Prompt A、B、C 分别增加了什么；
- 使用同一批输入比较不同 Prompt；
- 用明确评分标准，而不是“我感觉这个更好”；
- 找出至少一个模型失败案例；
- 解释失败究竟是 Prompt 不清楚、上下文不足，还是模型本身判断错误；
- 将实验代码、测试数据、结果和结论全部提交到 GitHub。

最终验收问题：

1. 为什么“请解释这个词”通常不够稳定？
2. 为什么明确输出字段会改善结果？
3. 为什么固定测试集很重要？
4. 为什么不能只拿一个例子判断 Prompt 好坏？
5. Prompt 写得越长，是否一定越好？
6. 什么情况下应该停止继续改 Prompt，转而修改代码、数据或模型？

你今天真正要形成的能力是：

> 能把一个自然语言需求，改写成一个可测试、可比较、可迭代的模型任务。
