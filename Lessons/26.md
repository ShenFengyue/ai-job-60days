**每次修改代码，都要手动运行测试吗？如果忘了怎么办？**

今天学习 GitHub Actions，让你每次推送代码或提交 Pull Request 时，GitHub 自动安装 Python 依赖、运行测试，并告诉你代码是否通过检查。

这叫 **CI（Continuous Integration，持续集成）**。它是 AI 应用开发岗位中很实用的一项工程能力。[GitHub Docs](https://docs.github.com/en/actions/tutorials/build-and-test-code/python?learn=continuous_integration&learnProduct=actions&utm_source=chatgpt.com)

## 1. 今日学习目标

重点理解：GitHub Actions 会在一个独立的运行环境中执行测试，不会直接使用你自己电脑上的 Python 虚拟环境。[GitHub Docs](https://docs.github.com/en/actions/tutorials/build-and-test-code/python?learn=continuous_integration&learnProduct=actions&utm_source=chatgpt.com)

## 3. 必须完成的 Coding Practice

### 第一步：确认本地测试通过

进入你的 `rag-agent` 项目目录，运行：

```
pytest -v
```

先确保本地测试能够通过。如果本地都失败了，自动化工作流只会重复报告同样的问题。

如果昨天的 `test_api.py` 使用了 FastAPI 的 `TestClient`，确保项目已经安装 `httpx`。

### 第二步：准备测试依赖

在项目根目录创建 `requirements-dev.txt`：

```
-r requirements.txt
pytest
httpx
```

这样，开发和测试依赖与项目的基本运行依赖分开管理。

### 第三步：创建 GitHub Actions 工作流

在项目根目录创建以下文件：

```
rag-agent/
└── .github/
    └── workflows/
        └── ci.yml
```

注意：`.github` 和 `workflows` 都是目录，`ci.yml` 是文件。

将以下内容写入 `ci.yml`：

```
name: Python CI

on:
  push:
  pull_request:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v7

      - name: Set up Python
        uses: actions/setup-python@v7
        with:
          python-version: "3.12"
          cache: pip
          cache-dependency-path: requirements-dev.txt

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements-dev.txt

      - name: Run tests
        run: pytest -v
```

这段配置可以理解为：

| 配置               | 作用                           |
| ------------------ | ------------------------------ |
| `on: push`         | 推送代码时运行                 |
| `on: pull_request` | 提交 Pull Request 时运行       |
| `runs-on`          | 使用 GitHub 提供的 Ubuntu 环境 |
| `setup-python`     | 安装指定版本的 Python          |
| `pip install`      | 安装项目依赖                   |
| `pytest -v`        | 运行测试并显示结果             |
| `permissions`      | 将工作流的仓库权限限制为只读   |

GitHub 官方文档也采用这种基本流程：准备 Python 环境、安装依赖、运行测试。[GitHub Docs](https://docs.github.com/en/actions/tutorials/build-and-test-code/python?learn=continuous_integration&learnProduct=actions&utm_source=chatgpt.com)

**注意：** 这里假设你的项目确实支持 Python 3.12。如果实际项目使用其他版本，应根据依赖兼容性调整。

另外，示例中的 `@v7` 是便于入门的版本标签。正式项目还可以按照 GitHub 安全指南，将第三方 Actions 固定到经过验证的完整提交 SHA。[GitHub Docs](https://docs.github.com/en/actions/how-tos/secure-your-work?utm_source=chatgpt.com)

### 第四步：推送到 GitHub

在项目根目录运行：

```
git add .
git commit -m "Day 26: add GitHub Actions CI"
git push
```

然后打开你的 GitHub 仓库，点击顶部的 **Actions**。

你应该能看到名为 `Python CI` 的工作流开始运行。

等待它完成：

- 绿色勾号：测试通过。
- 红色叉号：工作流失败，需要查看日志。

### 第五步：亲自制造一次失败

为了确认工作流确实有效，可以做一次小实验：

1. 临时修改某个测试，让断言必然失败。
2. 提交并推送。
3. 打开 GitHub Actions，确认工作流变红。
4. 恢复正确的测试。
5. 再次推送，确认工作流变绿。

**这一步很重要：你不仅要知道测试通过了，还要证明测试能够发现错误。**

如果工作流失败，先检查 `requirements-dev.txt` 是否包含所有必要依赖，以及测试是否意外调用了真实模型 API。

### 两道面试题

**Q1：CI 是什么？为什么 AI 应用项目也需要 CI？**

答题思路：CI 会在代码变更后自动执行构建或测试，尽早发现错误，避免修改某个模块时意外破坏其他功能。AI 应用同样需要保证 API、数据验证和业务逻辑的基本正确性。

**Q2：为什么不能直接在 CI 中调用真实的大模型 API 测试所有接口？**

答题思路：真实模型调用可能产生费用、延迟和不稳定输出，还可能受 API 配额或网络影响。基础测试应通过 Mock 验证程序逻辑；真实模型行为则通过独立的集成测试和评测集检查。
