# Day 58 / 60：Interview Simulation——完整技术面试模拟

**日期：2026 年 11 月 16 日。**

今天把知识、项目与表达放到真实面试节奏中。模拟不是证明自己没有短板，而是找出最影响通过率的短板。

## 1. 今日目标

完成一次技术问答模拟和一次项目深挖；记录问题、回答证据、失误和下一步修复。

## 2. 模拟流程（约 60–75 分钟）

- 5 分钟：自我介绍与求职方向。
- 15 分钟：Python/API 基础。
- 15 分钟：RAG/Agent 原理与取舍。
- 20 分钟：项目深挖。
- 10 分钟：系统设计或调试题。
- 5 分钟：反问面试官。

可请朋友模拟，也可录音后自己回放。尽量不看笔记；遇到不会的问题先澄清需求、说明假设，再推导。

## 3. 评分标准

每题 0–2 分：
- 0：无法回答或概念错误。
- 1：知道定义，但无法联系项目或解释取舍。
- 2：能给出准确解释、实际证据、边界和 trade-off。

评估准确性、结构、项目真实性、排障能力、安全意识和沟通清晰度。分数用于找问题，不是能力的绝对测量。

## 4. 项目深挖必问

1. 画出系统架构和请求数据流。
2. 最关键的技术决策是什么？有哪些备选？
3. 发生过什么具体故障？如何定位？
4. 如何评估 RAG/Agent 是否有效？
5. 如何处理模型超时、429、工具失败？
6. 如何防止数据泄露和工具越权？
7. 请求量增长 10 倍，先优化哪里？
8. 哪个功能尚未完成？下一步怎么做？

## 5. Coding / Debug 练习

任选一个小任务：写分页函数、实现重试策略、修复异步阻塞、写 RAG 评估函数。限时 20 分钟，边写边解释。不要只展示最终答案，要说出假设和测试边界。

## 6. Deliverable

创建 `job-search/mock-interview.md`，记录问题、原始回答、评分、证据缺口和 3 个优先改进项。按“面试影响 × 修复成本”排序。

```bash
git add job-search/mock-interview.md
git commit -m "Day 58: complete technical interview simulation"
git push
```

验收：完成一次完整模拟；记录至少 10 个问题；选出 3 个高影响缺口；每个缺口有具体练习或证据补充计划。

**提醒：** 不要因一道不会的题否定整个方向；把它转化成可验收的训练任务。
