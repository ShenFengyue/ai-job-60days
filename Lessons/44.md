## 3. Coding Practice：制作 AI 成本计算器

今天创建：

```
exercises/day46-cost-engineering/cost_calculator.py
```

不需要 API Key，不需要调用模型。先把成本计算逻辑写对。

假设你的产品平均每次请求：

- 输入：1,200 Tokens
- 输出：300 Tokens
- 请求量：1,000 / 10,000 / 100,000 次

下面是可以直接运行的初始代码：

```
requests_list = [1000, 10000, 100000]

# 每百万 Token 的非高峰价格
prices = {
    "deepseek-flash": {
        "hit": 0.003,
        "miss": 0.15,
        "output": 0.60
    },
    "deepseek-v4-pro": {
        "hit": 0.022,
        "miss": 0.66,
        "output": 1.98
    }
}

avg_input = 1200
avg_output = 300

for model, price in prices.items():
    for cache_rate in [0.0, 0.7]:
        print(f"\n{model}, cache rate: {cache_rate:.0%}")

        for count in requests_list:
            total_input = count * avg_input
            cached = total_input * cache_rate
            uncached = total_input - cached
            output = count * avg_output

            cost = (
                cached * price["hit"]
                + uncached * price["miss"]
                + output * price["output"]
            ) / 1_000_000

            print(f"{count:>8} requests: ${cost:.4f}")
```

你要做的不是单纯复制，而是：

1. 运行代码，观察不同请求量下的成本。
2. 修改平均输入和输出 Token 数，观察结果。
3. 修改缓存命中率，比较成本变化。
4. 自己增加高峰时段的计算。

### 先看一组计算结果

在上述假设下，非高峰时段：

| 请求量  | Flash，无缓存 | Pro，无缓存 |
| ------- | ------------- | ----------- |
| 1,000   | $0.36         | $1.386      |
| 10,000  | $3.60         | $13.86      |
| 100,000 | $36.00        | $138.60     |

如果输入 Token 的缓存命中率达到 70%：

| 请求量  | Flash，70% 命中 | Pro，70% 命中 |
| ------- | --------------- | ------------- |
| 1,000   | $0.237          | $0.850        |
| 10,000  | $2.365          | $8.501        |
| 100,000 | $23.652         | $85.008       |

注意：70% 是假设值，不代表实际能达到。高峰价格则是上面非高峰价格的两倍。

从这组数据可以发现：缓存并不是让所有费用都下降 70%，因为输出 Token 的费用并没有因此减少。

这就是今天要掌握的成本结构思维。

今天还要记住五种常见的降本方法：

- 选择合适的模型，而不是始终使用最贵的模型。
- 减少不必要的上下文。
- 缓存重复请求和可复用结果。
- 控制输出长度。
- 减少 Agent 无意义的循环和重复工具调用。
