# Day 29 / 60：Reranking——让 RAG 找到的资料排得更准确

**日期：2026 年 10 月 18 日。进度已核对：今天是 Day 29，不跳到 Day 30 或 Day 31。**

昨天，你为 RAG 加入了 Hybrid Search，用语义检索与 BM25 扩大候选文档范围。

今天解决下一个问题：**找到了 20 篇可能相关的文档，怎样把最有用的几篇排到前面？**

答案是 Reranking（重排序）。今天用一个真正的重排序模型，为你的 `rag-agent` 建立第二阶段检索，并通过评测验证效果。

## 1. 今日学习目标

理解并实现两阶段检索：

- **第一阶段：Retrieval。** 使用昨天的 Hybrid Search，快速找出 Top 20 候选文档。
- **第二阶段：Reranking。** 使用更深入的模型，逐一评估用户问题与候选文档的相关性，重新排列顺序。
- **最终输出：** 选出 Top 5 文档，交给 LLM 生成答案。

这种架构的原因是：向量检索适合快速筛选大量文档，而 Cross-Encoder 会同时处理问题和文档，通常能更精细地判断相关性，但计算成本更高。因此，我们只对少量候选文档运行它。[SentenceTransformers](https://www.sbert.net/docs/quickstart.html)

今天的技术路线：

```
用户问题
   │
   ▼
Hybrid Search
Dense + BM25 + RRF
   │
   ▼
Top 20 候选文档
   │
   ▼
Cross-Encoder Reranker
逐篇评估问题与文档的相关性
   │
   ▼
按相关性重新排序
   │
   ▼
Top 5 文档
   │
   ▼
LLM 生成答案
```

### 第二步：创建 `retrieval/reranker.py`

下面的代码使用 `BAAI/bge-reranker-v2-m3`，输入是查询和候选文档，输出是重新排序后的文档。

```
from sentence_transformers import CrossEncoder


MODEL_NAME = "BAAI/bge-reranker-v2-m3"


class Reranker:
    def __init__(self, model_name: str = MODEL_NAME):
        # 模型只加载一次，不要每个请求都重新加载
        self.model = CrossEncoder(model_name)

    def rerank(
        self,
        query: str,
        candidates: list[dict],
        top_n: int = 5,
    ) -> list[dict]:
        if not candidates or top_n <= 0:
            return []

        pairs = [
            (query, item["text"])
            for item in candidates
        ]

        scores = self.model.predict(
            pairs,
            batch_size=8,
            show_progress_bar=False,
        )

        ranked = []

        for item, score in zip(candidates, scores):
            ranked.append({
                **item,
                "rerank_score": float(score),
            })

        ranked.sort(
            key=lambda item: item["rerank_score"],
            reverse=True,
        )

        return ranked[:top_n]
```

这里假设候选文档的结构如下：

```
candidates = [
    {
        "id": "doc_01",
        "text": "API error E104 indicates authentication failure.",
    },
    {
        "id": "doc_02",
        "text": "Authentication verifies a user's identity.",
    },
]
```

如果你昨天的项目使用不同的字段名，例如 `chunk_id` 或 `content`，只需修改对应字段，不要重写原有检索代码。

**重要：** `rerank_score` 是模型用于排序的相关性分数，不是经过校准的概率，也不能直接当成答案正确率。

沿用昨天的 `evaluation/retrieval_cases.json`。

建议今天重点比较 **MRR@5 和 nDCG@5**：

- **MRR@5**：第一个相关文档排得越靠前，得分越高。
- **nDCG@5**：综合考虑前五名中各文档的相关性等级及其排名。

另外，保留昨天的 `Recall@20`，检查相关文档是否已经进入候选集。

这里有一个很重要的工程判断：

**Reranker 只能重新排列已经检索到的候选文档，无法找回根本没有进入候选集的文档。**

因此，如果正确答案不在 Hybrid Search 的 Top 20 里，今天的重排序模型也无法凭空把它找出来。

### 第五步：增加自动化测试

创建 `tests/test_reranker.py`。

今天先使用 Mock 模型测试排序逻辑，不需要每次运行测试都下载模型。

```
from retrieval.reranker import Reranker


class FakeModel:
    def predict(
        self,
        pairs,
        batch_size=8,
        show_progress_bar=False,
    ):
        # 第二篇文档更相关
        return [0.1, 0.9]


def test_reranker_orders_by_score():
    reranker = Reranker.__new__(Reranker)
    reranker.model = FakeModel()

    candidates = [
        {"id": "doc_01", "text": "Less relevant"},
        {"id": "doc_02", "text": "More relevant"},
    ]

    results = reranker.rerank(
        query="test query",
        candidates=candidates,
        top_n=2,
    )

    assert results[0]["id"] == "doc_02"
    assert results[1]["id"] == "doc_01"


def test_reranker_respects_top_n():
    reranker = Reranker.__new__(Reranker)
    reranker.model = FakeModel()

    candidates = [
        {"id": "doc_01", "text": "Document one"},
        {"id": "doc_02", "text": "Document two"},
    ]

    results = reranker.rerank(
        query="test query",
        candidates=candidates,
        top_n=1,
    )

    assert len(results) == 1
    assert results[0]["id"] == "doc_02"


def test_reranker_empty_candidates():
    reranker = Reranker.__new__(Reranker)
    reranker.model = FakeModel()

    assert reranker.rerank(
        query="test query",
        candidates=[],
    ) == []
```

运行：

```
pytest -v
```

然后再进行一次真实模型测试，确认模型确实能够给候选文档评分并输出排序结果。

### 两道面试题

**Q1：为什么 RAG 系统需要 Reranker？**

答题思路：第一阶段检索强调效率，快速找出可能相关的候选文档；第二阶段使用 Cross-Encoder 联合处理查询和文档，对相关性进行更细致的判断，从而改善最终排序。代价是增加推理延迟和计算开销。

**Q2：加入 Reranker 后，为什么答案质量仍然可能没有提升？**

答题思路：正确文档可能没有进入候选集；重排序模型可能判断错误；文档切片可能不完整；最终生成模型也可能没有正确利用证据。应通过检索指标、排序指标和端到端答案评测逐层定位问题。
