## 3. 必须完成的 Coding Practice

在现有项目里创建 `services/model_client.py`。如果你使用的模型 SDK 自带超时机制，优先使用它；以下是使用 HTTPX 直接请求外部服务的通用示例：

```
import httpx


class ModelServiceError(Exception):
    pass


def call_model(url: str, payload: dict) -> dict:
    try:
        response = httpx.post(
            url,
            json=payload,
            timeout=httpx.Timeout(
                30.0,
                connect=5.0,
            ),
        )
        response.raise_for_status()
        return response.json()

    except httpx.TimeoutException as exc:
        raise ModelServiceError(
            "Model request timed out"
        ) from exc

    except httpx.HTTPStatusError as exc:
        raise ModelServiceError(
            f"Model service returned HTTP "
            f"{exc.response.status_code}"
        ) from exc

    except httpx.RequestError as exc:
        raise ModelServiceError(
            "Unable to reach model service"
        ) from exc
```

这里的 URL 和请求体需要根据你实际使用的模型供应商进行适配。不要直接将这个示例当成某个供应商的完整 API 客户端。

然后完成两项工作：

1. 在 FastAPI 中增加 `GET /health`，正常时返回 `{"status": "ok"}`。
2. 使用 Mock 编写测试，分别模拟请求超时、HTTP 500 和正常返回，确保程序按预期处理。

健康检查可以验证服务进程是否正常，但它不一定能证明模型供应商可用。两者应当分开监控。

今天练习两个面试问题：

Q1：为什么调用大模型 API 必须设置超时？

答题要点：外部网络和供应商服务可能出现延迟或故障。超时能限制请求等待时间，避免资源长期被占用，并让上层系统执行明确的失败处理。

Q2：模型 API 返回 HTTP 500 时，应该立即重试吗？

答题要点：不能无条件重试。需要考虑错误类型、请求是否幂等、重试次数、退避策略和总耗时预算。对可能产生重复费用或副作用的请求，尤其要谨慎。
