# Day 27 / 60：Web Search 与私有 RAG 工具路由

**日期：2026 年 10 月 16 日。**

昨天的 Research Agent 已能调用工具。今天让它判断问题应该查公开网页、私有知识库，还是两者都查。

## 1. 今日目标

实现可解释的路由：最新新闻、价格、版本、政策走 Web Search；“我上传的文件”“内部知识库”走私有 RAG；明确要求结合两种来源时走 both。

```text
问题 → 路由决策 → Web / Private RAG / Both → 证据整理 → 带来源回答
```

路由器决定去哪里找信息，不负责编造答案。工具无结果或失败时必须明确告知。

## 2. 核心概念

- Private knowledge：用户上传的 PDF、笔记或内部数据。
- Web Search：适合时效性较强的公开信息。
- Routing：按任务选择工具。
- Evidence fusion：合并证据但保留各自来源、时间和可信度。
- Fallback：工具失败时提供部分结果或说明限制。

先做规则路由，再考虑 LLM 分类。规则更容易测试，也更容易定位错误。

## 4. Coding Practice

创建 `exercises/day27-routing/`，实现 `RouteDecision(route, reason)`，route 只允许 `web/private/both`。定义统一工具接口，工具结果统一为 `{source, content, url}`。

规则原型：

```python
from typing import Literal
from pydantic import BaseModel

class RouteDecision(BaseModel):
    route: Literal["web", "private", "both"]
    reason: str

def choose_route(question: str) -> RouteDecision:
    web_words = ["今天", "最新", "现在", "近期", "价格", "版本"]
    private_words = ["我上传的", "我的文档", "这份 PDF", "知识库"]
    web = any(x in question for x in web_words)
    private = any(x in question for x in private_words)
    if web and private:
        return RouteDecision(route="both", reason="同时需要实时信息和私有资料")
    if web:
        return RouteDecision(route="web", reason="问题有时效性")
    return RouteDecision(route="private", reason="默认检索已有私有资料")
```

这是教学规则，不是完整语义理解。后续可用 LLM 分类，但必须用固定 schema 校验输出，并在分类失败时有默认策略。

## 5. 必须测试

1. “我上传的论文如何解释工作记忆？”→ private。
2. “今天最新 Python 版本是什么？”→ web。
3. “结合我的报告和最新政策分析”→ both。
4. Web 超时不能伪造网页证据。
5. 私有检索为空要明确说明。
6. 两种来源冲突时分开呈现，不要悄悄选一边。

工具调用设置 timeout、错误处理和日志。记录路由理由、工具耗时与结果数量，但不要记录密钥或完整隐私内容。
