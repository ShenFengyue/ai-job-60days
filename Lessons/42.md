## 2. 核心概念

- Settings：从环境变量读取运行配置，不把环境差异写死在代码里。
- Dependency Injection：由框架或组合根提供依赖，路由不负责自行创建所有资源。
- Async I/O：等待网络/数据库等 I/O 时释放事件循环，不等于 CPU 计算自动变快。
- Lifespan：管理应用启动和关闭时的资源。
- TestClient：在测试中调用 ASGI 应用，不必启动真实公网服务器。

## 4. Coding Practice

整理为：

```text
app/
├── main.py
├── core/config.py
├── api/routes/
├── services/
├── repositories/
├── schemas/
└── tests/
```

用 Pydantic Settings 从环境变量读取配置：

```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    app_name: str = "AI Service"
    environment: str = "development"
    database_url: str
    llm_api_key: str

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )

settings = Settings()
```

不要在代码里提供真实密钥默认值。生产环境从部署平台注入环境变量，`.env` 仅用于本地开发且不得提交。

将模型调用放进 service 层，数据库操作放进 repository 层。路由负责 HTTP 输入输出，不要在每个 endpoint 里重复创建模型客户端。

使用依赖注入提供服务对象。为模型客户端设计接口，测试时注入 fake/mock 实现，避免单元测试真实调用模型、产生费用或依赖外部网络。

## 5. Async 判断

网络请求、异步数据库驱动适合 async；CPU 密集型计算不会因为加上 `async` 就自动并行。不要在 async endpoint 中直接执行长时间阻塞操作。第三方 SDK 若只有同步接口，应评估线程池、异步替代或后台任务。

## 6. 测试

至少覆盖：配置缺失时应用明确失败；健康检查正常；请求校验错误返回 422；服务层异常映射为安全的错误响应；mock 模型调用不访问真实 API；数据库依赖可替换。
