# Day 32 / 60：数据库基础——保存用户、会话与消息

**日期：2026 年 10 月 21 日。**

API 进程重启后，内存变量会消失。真实产品必须把用户、对话和设置保存到数据库。今天从 SQL 和关系建模入手。

## 1. 今日目标

设计并实现 users、conversations、messages 三张表，完成 CRUD，理解主键、外键、索引和事务。

```text
User 1 ── N Conversation 1 ── N Message
```

不要把所有聊天记录塞进一个巨大 JSON 字段。拆表才能分页、检索、统计和按用户隔离数据。

## 2. 核心概念

- Table：同类记录集合。
- Primary key：唯一标识一行。
- Foreign key：引用另一张表，表达关系。
- Index：加速查询，但增加写入和存储成本。
- CRUD：增删改查。
- Transaction：一组操作整体提交或回滚。
- Migration：可追踪地修改数据库结构。

SQLite 适合本地练习；多用户部署通常考虑 PostgreSQL。

## 4. 数据模型练习

创建 `exercises/day32-database/schema.sql`：

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL
);

CREATE TABLE conversations (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  title TEXT NOT NULL,
  created_at TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE TABLE messages (
  id INTEGER PRIMARY KEY,
  conversation_id INTEGER NOT NULL,
  role TEXT NOT NULL CHECK(role IN ('system','user','assistant','tool')),
  content TEXT NOT NULL,
  created_at TEXT NOT NULL,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id)
);
```

使用 Python `sqlite3` 实现初始化、创建用户、创建会话、写入消息、列出会话、按时间读取消息、修改标题和删除会话。明确删除会话时消息是级联删除还是显式删除。

查询练习：

```sql
SELECT m.role, m.content, m.created_at
FROM messages m
JOIN conversations c ON c.id = m.conversation_id
WHERE c.id = ?
ORDER BY m.created_at, m.id
LIMIT ? OFFSET ?;
```

索引示例：

```sql
CREATE INDEX idx_conversations_user_created
ON conversations(user_id, created_at);
CREATE INDEX idx_messages_conversation_created
ON messages(conversation_id, created_at);
```

所有输入都用参数化查询，不要拼接 SQL 字符串。

## 5. 测试与安全

测试重复邮箱被拒绝、外键约束生效、不同用户不能读取彼此会话、分页顺序稳定、删除行为符合设计。测试数据使用虚构信息，不提交真实隐私或密钥。

注意 SQLite 默认外键约束需要显式启用：连接后执行 `PRAGMA foreign_keys = ON`。
