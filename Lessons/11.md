## Day 11｜最小 RAG 问答：让模型基于你的文档回答，而不是凭记忆作答

今天是 **Day 11（2026 年 9 月 15 日）**。前 10 天你已经完成了：

```
Python
→ API
→ Git/GitHub
→ Prompt
→ 结构化输出
→ Embeddings
→ FAISS

```

今天把这些组件首次串成一条完整的 **Retrieval-Augmented Generation（RAG）** 链路：

```
用户问题
→ 问题 embedding
→ 从 FAISS 检索相关 chunks
→ 把 chunks 放进 prompt
→ LLM 基于上下文回答
→ 返回来源
```

今天的目标不是做“高级 RAG”，而是做一个**可解释的最小 RAG**：你能看到它检索了什么、为什么这样回答、证据来自哪里。

------

## 1）今日学习目标

完成今天后，你应该能：

- 用自己的话解释 RAG 的三个阶段：
  1. Retrieve：检索；
  2. Augment：补充上下文；
  3. Generate：生成回答；
- 将 Day 10 的 chunks 建成 embedding + FAISS 索引；
- 根据用户问题检索 top-k 文本片段；
- 将检索结果作为上下文发送给 LLM；
- 强制模型“只根据上下文回答”；
- 在回答中返回引用的 chunk ID；
- 识别“检索错了”和“模型读错了”是两个不同问题。

今天最重要的工程判断是：

> RAG 不是“给模型塞一堆文本”，而是让模型先拿到**相关、可追溯、数量适当**的文本。

### 第一步：实现检索函数

```
rag.py
import json
from pathlib import Path

import faiss
from sentence_transformers import SentenceTransformer


MODEL_NAME = "sentence-transformers/all-MiniLM-L6-v2"


def load_chunks(path: str = "chunks.json") -> list[dict]:
    return json.loads(Path(path).read_text(encoding="utf-8"))


def build_index(chunks: list[dict]):
    model = SentenceTransformer(MODEL_NAME)

    texts = [chunk["text"] for chunk in chunks]
    embeddings = model.encode(
        texts,
        convert_to_numpy=True,
        normalize_embeddings=True,
    ).astype("float32")

    index = faiss.IndexFlatIP(embeddings.shape[1])
    index.add(embeddings)

    return model, index


def retrieve(
    query: str,
    model,
    index,
    chunks: list[dict],
    top_k: int = 3,
) -> list[dict]:
    query_embedding = model.encode(
        [query],
        convert_to_numpy=True,
        normalize_embeddings=True,
    ).astype("float32")

    scores, indices = index.search(query_embedding, top_k)

    results = []

    for score, idx in zip(scores[0], indices[0]):
        chunk = chunks[int(idx)].copy()
        chunk["score"] = round(float(score), 4)
        results.append(chunk)

    return results
```

### 第二步：实现上下文构造

```
def build_context(retrieved_chunks: list[dict]) -> str:
    sections = []

    for chunk in retrieved_chunks:
        sections.append(
            f"[{chunk['chunk_id']}]\n{chunk['text']}"
        )

    return "\n\n".join(sections)
```

这里必须保留 `chunk_id`，因为后面要让模型引用来源。

### 第三步：调用 LLM 生成基于证据的答案

```
main.py
import json
import os
from pathlib import Path

import requests
from dotenv import load_dotenv

from rag import build_context, build_index, load_chunks, retrieve


load_dotenv()

API_KEY = os.getenv("DEEPSEEK_API_KEY")
MODEL = os.getenv("DEEPSEEK_MODEL", "deepseek-v4-flash")
URL = "https://api.deepseek.com/chat/completions"


def generate_answer(question: str, context: str) -> str:
    system_prompt = """
You are a grounded question-answering assistant.

Answer the user's question using only the provided context.

Rules:
1. If the context does not contain enough information, say:
   "I don't know based on the provided context."
2. Do not invent facts.
3. Cite the chunk IDs used in your answer.
4. Keep the answer concise.
"""

    user_prompt = f"""
Context:
{context}

Question:
{question}
"""

    response = requests.post(
        URL,
        headers={
            "Authorization": f"Bearer {API_KEY}",
            "Content-Type": "application/json",
        },
        json={
            "model": MODEL,
            "messages": [
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_prompt},
            ],
            "temperature": 0.1,
            "stream": False,
        },
        timeout=30,
    )

    response.raise_for_status()
    data = response.json()

    return data["choices"][0]["message"]["content"]


def main():
    chunks = load_chunks()
    model, index = build_index(chunks)

    questions = [
        "What is the main purpose of this document?",
        "What practical steps are recommended?",
        "Which part is most relevant to a beginner?",
        "What does the document say about quantum computing?",
    ]

    all_results = []

    for question in questions:
        retrieved = retrieve(
            query=question,
            model=model,
            index=index,
            chunks=chunks,
            top_k=3,
        )

        context = build_context(retrieved)
        answer = generate_answer(question, context)

        result = {
            "question": question,
            "retrieved_chunks": [
                {
                    "chunk_id": chunk["chunk_id"],
                    "score": chunk["score"],
                    "text": chunk["text"],
                }
                for chunk in retrieved
            ],
            "answer": answer,
        }

        all_results.append(result)

        print("\n" + "=" * 70)
        print("Question:", question)
        print("\nRetrieved chunks:")
        for chunk in retrieved:
            print(f"- {chunk['chunk_id']} ({chunk['score']}): {chunk['text'][:120]}...")
        print("\nAnswer:")
        print(answer)

    Path("results.json").write_text(
        json.dumps(all_results, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )


if __name__ == "__main__":
    main()
```

### 第五步：做两个对照实验

#### 实验 A：有 RAG vs 无 RAG

- 有 RAG：发送问题 + retrieved context；
- 无 RAG：只发送问题。

比较：

- 是否更容易回答文档专属问题；
- 是否更容易承认不知道；
- 是否减少了无根据的内容。

#### 实验 B：top-k = 1 vs top-k = 3

观察：

- `k=1` 是否信息不完整；
- `k=3` 是否带来更多噪音；
- 哪种问题适合更多 chunks。

## 5）今天的验收标准

Day 11 通过，必须满足：

- 能把 Day 10 的 chunks 送入 embedding + FAISS；
- 能针对用户问题返回 top-k chunks；
- 能把检索结果拼成上下文；
- 能调用 LLM 基于上下文回答；
- 能返回来源 chunk ID；
- 对文档中没有答案的问题，能明确说信息不足；
- 能完成有 RAG / 无 RAG 对比；
- 能完成 top-k=1 / top-k=3 对比；
- `results.json` 保存了检索过程和最终回答；
- 代码和 README 已提交到 GitHub。

最终验收问题：

1. RAG 中哪一步负责找信息？
2. 哪一步负责把信息交给模型？
3. 为什么“检索结果错了”与“模型生成错了”是两种不同故障？
4. 为什么不能只看最终答案判断 RAG 是否有效？
5. 为什么必须保留 chunk ID 和来源？
6. top-k 太小、太大分别可能有什么问题？
7. 文档没有答案时，系统应该怎么做？

最终通过标准：

> 你能输入一个问题，看到系统先检索哪些 chunks，再看到模型基于这些 chunks 生成带来源的回答；当证据不足时，系统会拒绝编造。
