# Day 21 / 60：让 Agent 的运行过程变得可观察

**日期：2026 年 10 月 10 日。今天是 Day 21，不改变重置后的进度。**

昨天你学习了 Agent Evaluation，开始用数据判断 Agent 是否有效。今天进入下一步：**当 Agent 失败时，你能不能看清它为什么失败？**

生产级 AI 应用不只是能回答问题，还需要能够追踪执行步骤、发现错误、定位延迟，并为后续优化提供证据。今天我们用 **Langfuse** 为已有的 `rag-agent` 添加可观测性。[Hugging Face](https://huggingface.co/learn/agents-course/en/bonus-unit2/introduction?utm_source=chatgpt.com)

## 1. 今日学习目标

把现有 Agent 的执行过程变成一条可检查的 Trace（追踪记录）。

```
用户问题
   ↓
Agent 开始执行
   ↓
LLM 调用
   ↓
选择工具
   ↓
检索知识库 / 计算
   ↓
生成最终答案
   ↓
记录耗时、执行步骤与错误
```

先记住两个概念：

- **Trace**：一次任务从开始到结束的完整执行记录。
- **Span**：Trace 中的一个具体步骤，例如调用模型、检索知识库或使用计算器。

有了这些记录，你才能区分：究竟是模型回答错了、工具选错了、检索出了问题，还是某个步骤耗时过长。[Langfuse](https://langfuse.com/docs/observability/sdk/overview)

## 3. 必须完成的 Coding Practice

### 任务：为 `projects/rag-agent` 添加 Langfuse 追踪

**第一步：安装依赖。**

在你的项目虚拟环境中运行：

```
pip install langfuse
```

**第二步：配置密钥。**

在项目根目录创建 `.env`，填写从 Langfuse 项目设置中获取的密钥：

```
LANGFUSE_PUBLIC_KEY=你的公钥
LANGFUSE_SECRET_KEY=你的私钥
LANGFUSE_BASE_URL=https://cloud.langfuse.com
```

确保 `.env` 已加入 `.gitignore`，绝不能将密钥提交到 GitHub。官方 SDK 会从环境变量读取配置。[Langfuse](https://langfuse.com/docs/observability/sdk/overview?utm_source=chatgpt.com)

**第三步：为 Agent 和工具添加追踪。**

按照你现有代码的实际函数名修改下面的示例：

```
from langfuse import observe, get_client, propagate_attributes


@observe(as_type="tool")
def search_knowledge(query):
    # 保留你原来的知识库检索逻辑
    ...


@observe(as_type="tool")
def calculator(expression):
    # 保留你原来的计算逻辑
    ...


@observe(as_type="agent")
def run_agent(query, case_id="manual"):
    with propagate_attributes(
        metadata={
            "project": "rag-agent",
            "case_id": str(case_id),
            "version": "day21",
        }
    ):
        # 调用你原来的 Agent 主逻辑
        return existing_agent_run(query)


# 执行测试后，确保短生命周期程序中的追踪记录被发送
# 在程序结束前调用：
get_client().flush()
```

这里的 `...` 和 `existing_agent_run` 是占位内容，不是可以直接运行的完整实现。你需要保留原来的业务逻辑，只在对应函数上添加装饰器。`propagate_attributes()` 用于将测试用例等元数据传递给同一 Trace 中的子步骤。[Langfuse](https://langfuse.com/docs/observability/features/metadata?utm_source=chatgpt.com)

**第四步：运行 5 个测试用例。**

从昨天的 `evaluation/dataset.json` 中选取 5 个有代表性的用例：

1. 只需要知识库检索。
2. 只需要计算器。
3. 需要组合使用工具。
4. 不应该调用任何工具。
5. 一个你昨天发现过的失败案例。

登录 Langfuse，逐条检查 Trace。重点记录：

| 检查项     | 你需要确认的内容                |
| ---------- | ------------------------------- |
| 执行步骤   | Agent 是否按预期执行            |
| 工具调用   | 实际调用了什么工具              |
| 输入与输出 | 每一步收到了什么、返回了什么    |
| 延迟       | 哪个步骤最耗时                  |
| 错误       | 是否发生异常，异常出在哪一步    |
| 测试关联   | 能否通过 `case_id` 找到对应记录 |

注意：手动添加 `@observe` 可以追踪函数执行，但模型 Token 用量和费用不一定会自动出现。它们取决于模型调用的具体集成或额外埋点；今天不必为此扩展任务。

另外，只使用虚构测试数据，不要把个人信息、客户数据或 API 密钥发送到第三方平台。

### 两道面试题

**Q1：Logging、Monitoring 和 Tracing 有什么区别？**

思考方向：日志记录具体事件，Monitoring 关注预设指标和异常，Tracing 则帮助你还原一次请求经过了哪些步骤。它们互相补充，并不是互相替代。

**Q2：如果一个 Agent 回答错误，你如何定位问题？**

思考方向：先检查评测用例与预期行为，再沿 Trace 检查模型调用、检索结果、工具选择、工具执行和最终答案。确定问题所在后，修改代码或提示词，并重新运行回归测试。
