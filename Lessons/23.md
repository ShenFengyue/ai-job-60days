# Day 23 / 60：Structured Outputs——让 AI 输出真正可用的数据

**日期：2026 年 10 月 12 日。**

前几天，你的路线依次经过了 RAG、Agent、Evaluation、Observability 和性能优化。今天进入一个很实际的工程问题：

**AI 明明回答正确，为什么程序还是会报错？**

因为模型返回的可能是一段自然语言，而程序需要的是格式固定、字段明确、类型正确的数据。

今天，我们使用 **Pydantic + JSON Schema**，为你的 `rag-agent` 建立可靠的结构化输出层。

## 1. 今日学习目标

理解并实践三个概念：

| 概念        | 解决什么问题                         |
| ----------- | ------------------------------------ |
| JSON        | 让数据采用机器可读取的格式           |
| JSON Schema | 定义数据必须具备哪些字段、类型和约束 |
| Pydantic    | 在 Python 中验证数据是否符合预期     |

例如，普通 AI 回答可能是：

> 我找到了相关资料，答案是 42。

而程序需要的可能是：

```
{
  "status": "answered",
  "answer": "42",
  "sources": ["doc_01"],
  "needs_human_review": false
}
```

这样，前端可以根据 `status` 显示不同界面，程序可以读取 `sources`，业务逻辑也能判断是否需要人工复核。

注意一个关键区别：**JSON Mode 只保证输出是有效 JSON，并不保证它符合指定的 Schema；支持的原生 Structured Outputs 则可以进一步约束输出结构。** [OpenAI Developers](https://developers.openai.com/api/docs/guides/structured-outputs)

## 2. 今天最值得看的 3 份材料

### ① OpenAI 官方：Structured Outputs

[Structured Outputs 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs?utm_source=chatgpt.com)

这是今天的主材料。重点看两个部分：

- 什么时候使用结构化响应，什么时候使用 Function Calling。
- Structured Outputs 与 JSON Mode 有什么区别。

简单理解：**让模型按固定格式回答，用结构化响应；让模型选择并调用程序工具，用 Function Calling。** [OpenAI Developers](https://developers.openai.com/api/docs/guides/structured-outputs)

注意：OpenAI 的原生结构化输出能力取决于模型和 API 支持情况，不要默认它可以直接用于你当前的 DeepSeek 接口。

### ② Pydantic 官方：JSON Schema

[Pydantic JSON Schema 文档](https://pydantic.dev/docs/validation/2.9/concepts/json_schema/?utm_source=chatgpt.com)

重点理解两个方法：

- `model_validate()`：验证 Python 字典等数据是否符合模型定义。
- `model_json_schema()`：生成对应的 JSON Schema。

为什么选它？因为即使模型提供商不支持原生 Structured Outputs，你也可以在 Python 应用端进行数据验证。[Pydantic](https://pydantic.dev/docs/validation/2.9/concepts/json_schema/)

### ③ Hugging Face Agents Course：Agent Actions

[Agent Actions：官方课程](https://github.com/huggingface/agents-course/blob/main/units/en/unit1/actions.mdx?utm_source=chatgpt.com)

重点看 Stop and Parse Approach：模型生成结构化动作，程序停止读取输出并解析数据，再决定调用哪个工具。

这部分直接关联你之前构建的 Agent。[GitHub](https://github.com/huggingface/agents-course/blob/main/units/en/unit1/actions.mdx)

### 任务：为 Agent 的最终回答建立数据契约

在现有项目中创建 `schemas.py`。

先安装依赖：

```
pip install "pydantic>=2,<3"
```

然后编写：

```
from typing import Literal

from pydantic import BaseModel, Field


class AgentResponse(BaseModel):
    status: Literal["answered", "no_answer", "error"]
    answer: str
    sources: list[str] = Field(default_factory=list)
    needs_human_review: bool = False
```

这定义了一个简单的数据契约：状态只能取三个值，答案必须是字符串，来源必须是字符串列表，人工复核标记必须是布尔值。

接下来创建 `test_schemas.py`：

```
import pytest
from pydantic import ValidationError

from schemas import AgentResponse


def test_valid_response():
    result = AgentResponse.model_validate({
        "status": "answered",
        "answer": "42",
        "sources": ["doc_01"],
        "needs_human_review": False,
    })

    assert result.status == "answered"
    assert result.answer == "42"


def test_invalid_status():
    with pytest.raises(ValidationError):
        AgentResponse.model_validate({
            "status": "maybe",
            "answer": "42",
        })


def test_invalid_sources():
    with pytest.raises(ValidationError):
        AgentResponse.model_validate({
            "status": "answered",
            "answer": "42",
            "sources": "doc_01",
        })


def test_missing_answer():
    with pytest.raises(ValidationError):
        AgentResponse.model_validate({
            "status": "answered",
        })


def test_default_values():
    result = AgentResponse.model_validate({
        "status": "no_answer",
        "answer": "",
    })

    assert result.sources == []
    assert result.needs_human_review is False
```

### 两道面试题

**Q1：JSON Mode 和 Structured Outputs 有什么区别？**

答题要点：JSON Mode 主要保证输出是合法 JSON；Structured Outputs 在支持的模型和接口上，还能约束输出符合指定 Schema。若原生能力不可用，可以在应用端用 Pydantic 验证，并实现必要的错误处理。

**Q2：Pydantic 验证通过，是否意味着 AI 的回答可信？**

答题要点：不是。Pydantic 检查的是数据类型、字段和约束，而不是事实真伪。答案的正确性仍需通过检索证据、业务规则和评测用例判断。
