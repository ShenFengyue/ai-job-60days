# Day 53 / 60：Agent 面试准备——工具调用、状态与可靠性

**日期：2026 年 11 月 11 日。**

Agent 面试重点不是“模型能自主思考”，而是你能否解释它如何选择动作、执行工具、保存状态、处理失败并验证结果。

## 1. 今日目标

完成 Agent 面试题库，能画出执行循环，并解释 tool calling 与普通函数调用、workflow 与 agent、memory 与 state 的区别。

## 2. 核心执行循环

```text
Receive task
    ↓
Observe state/context
    ↓
Decide next action
    ↓
Validate tool arguments
    ↓
Execute tool
    ↓
Observe result/error
    ↓
Continue / finish / ask user
```

模型提出工具调用意图；应用负责 schema 校验、权限检查、执行、超时、重试和结果回传。

## 3. 高频面试问题

**Q1：Tool calling 是什么？**  
模型按约定结构提出函数名和参数，应用验证并执行，再把结果交给模型继续处理。模型本身并没有直接获得函数权限。

**Q2：Agent 与固定 workflow 有何区别？**  
Workflow 的步骤和分支主要由程序预先定义；Agent 在运行时根据状态选择下一步。生产系统常采用受控 workflow + 局部 Agent，而不是完全放任模型。

**Q3：为什么需要状态？**  
保存任务目标、已完成步骤、工具结果和错误信息，避免每轮都从头猜测。状态应有 schema、版本和持久化策略。

**Q4：Memory 与 state 的区别？**  
State 是当前任务运行所需的工作状态；Memory 是跨任务保留的有用信息。记忆写入需要筛选、权限和删除策略。

**Q5：如何处理工具失败？**  
设置 timeout、区分可重试与不可重试错误、限制重试次数、使用幂等键避免重复副作用，并在无法恢复时请求用户或结束任务。

**Q6：如何防止工具越权？**  
服务端做身份与权限检查；模型给出的参数不可信；危险动作设置人工确认；工具只暴露最小权限能力。

**Q7：Agent 如何评估？**  
建立任务集，评估任务完成率、工具选择正确率、参数正确率、步骤数、成本、延迟和安全违规率。保留失败轨迹用于回归。

## 4. Coding Practice

选自己的 Research Agent，构建 15–20 个任务测试集。每个任务定义预期工具、参数约束、成功条件和禁止动作。至少覆盖：工具超时、无效参数、空结果、重复调用、权限拒绝、模型输出格式错误。

对每个任务保存执行轨迹（脱敏），比较成功率和平均工具调用次数。不要把模型“说自己完成了”当作成功；用外部状态验证副作用是否真的发生。
