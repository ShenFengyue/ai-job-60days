# Day 57 / 60：Resume + Portfolio——把工程证据转化为求职材料

**日期：2026 年 11 月 15 日。**

今天完成简历与作品集入口。简历不是技术清单，而是帮助招聘者快速判断你能否解决岗位问题的证据摘要。

## 1. 今日目标

产出一版针对 AI Application Engineer / LLM Application Engineer 的简历，以及一个可访问的作品集入口。

## 2. 简历原则

每条项目经历尽量包含：动作 + 技术/方法 + 解决的问题 + 可验证结果。

弱表达：“使用 Python、FastAPI、RAG 开发智能问答系统。”

更好的结构：“使用 FastAPI 构建文档问答 API，加入检索评估与引用校验；通过固定测试集比较检索策略，并记录失败案例。”如果有真实指标，可加入测试集规模、Recall@K、P95、成本等；没有数据就不要编数字。

## 3. 内容结构

1. 联系方式与 GitHub/作品集链接。
2. 目标岗位方向。
3. 技术技能：只列能解释和使用的技术。
4. 2–3 个代表项目：问题、贡献、架构、验证证据。
5. 教育经历与相关背景。
6. 其他与岗位相关的沟通、交付、用户理解经验。

技能分级可区分“熟练使用”“项目实践”“正在学习”，不要把只看过教程的技术列为熟练。

## 4. 作品集首页

每个项目放：一句话价值、真实 Demo、架构图、关键技术决策、测试/评估证据、GitHub 源码、已知限制。首屏不要堆砌所有技术关键词。

## 5. 今日任务

- 对照 3 个目标岗位 JD，提取共同要求。
- 选择最匹配的岗位族，调整简历顺序与关键词。
- 每个项目写 2–3 条证据型 bullet。
- 检查 GitHub README 与 pinned repositories。
- 请一位读者在 30 秒内回答：你适合什么岗位？最强项目是什么？证据在哪里？

## 6. 学习材料

- [Harvard Resume Guide](https://careerservices.fas.harvard.edu/resources/creating-a-resume/)
- [GitHub Profile README](https://docs.github.com/en/account-and-profile/setting-up-and-managing-your-github-profile/customizing-your-profile/managing-your-profile-readme)

## 7. Deliverable

```text
job-search/
├── resume-v1.md
└── portfolio-home.md
```

验收：简历长度合理；每条技术主张能举证；作品集链接有效；目标岗位明确；没有夸大或虚构量化成果。

**求职动作：** 用这版简历投递至少 1 个高度匹配岗位，并记录版本与日期。

## 证据要求
每条简历 bullet 都要能回答“我具体做了什么、解决什么问题、证据在哪、数字是否真实测量”。作品集首页只放真实 Demo、源码、架构、测试/评估和限制。请使用 [Job Search Evidence Kit — Day 57](../JOB-SEARCH-EVIDENCE-KIT.md#day-57--resume-and-portfolio-evidence)。
