# Day 39 / 60：Docker Compose——统一启动多服务应用

**日期：2026 年 10 月 28 日。**

真实 AI 应用可能同时有 API、PostgreSQL、Redis、向量数据库和前端。Compose 用一个 YAML 描述多容器应用，降低启动和配置成本。

## 1. 今日目标

用 Compose 启动 API 与数据库，理解服务名网络、端口、环境变量、volume 和 healthcheck。

“容器已启动”不等于“应用已就绪”：数据库进程存在，不代表它已经能接受连接。

## 2. 学习材料

- [Docker Compose Overview](https://docs.docker.com/compose/)
- [Compose Services](https://docs.docker.com/reference/compose-file/services/)
- [Startup Order](https://docs.docker.com/compose/how-tos/startup-order/)

## 3. Coding Practice

创建 `compose.yaml`。下面是 API + PostgreSQL 练习结构；若项目使用 SQLite，就先只保留 API，不要为练习强行迁移。

```yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    env_file: .env
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  postgres_data:
```

真实密码放在本地 `.env`，不要提交；`.env.example` 只放变量名和占位说明。Compose 网络内 API 应使用主机名 `db` 和端口 5432，而不是 localhost。

## 4. 运行与检查

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps
docker compose logs -f api
docker compose down
```

访问健康检查与 RAG 接口。重启后确认必要数据仍在。谨慎使用 `docker compose down -v`，它会删除命名 volume。

## 5. 配置解释

- build：从 Dockerfile 构建。
- ports：宿主机到容器端口映射。
- env_file/environment：注入配置。
- volumes：持久化数据。
- depends_on：声明依赖；配合 healthcheck 才能等待健康状态。
- restart：退出后的重启策略。

## 6. Deliverable

提交 `compose.yaml`、`.env.example`、更新后的 `.gitignore` 和 README。README 说明启动、查看日志、停止、数据持久化与环境变量。

```bash
git add compose.yaml .env.example .gitignore README.md
git commit -m "Day 39: add Docker Compose deployment"
git push
```

验收：配置检查通过；服务健康；API 可访问；日志可读；必要数据重启后保留；没有真实密钥。
