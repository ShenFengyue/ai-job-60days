## 第一部分：自己实现最小 Trace

新建：

```
# tracer.py

import time
import uuid


class Trace:
    def __init__(self, question: str):
        self.trace_id = str(uuid.uuid4())
        self.question = question
        self.events = []
        self.start_time = time.perf_counter()

    def log(self, event_type: str, **data):
        self.events.append({
            "event_type": event_type,
            "timestamp": time.time(),
            **data,
        })

    def finish(self):
        self.total_latency_ms = round(
            (time.perf_counter() - self.start_time) * 1000,
            2,
        )

        return {
            "trace_id": self.trace_id,
            "question": self.question,
            "total_latency_ms": self.total_latency_ms,
            "events": self.events,
        }
```

然后在 Agent 中记录：

```
agent_start
llm_request
tool_selected
tool_start
tool_end
llm_request
agent_end
```

例如：

```
{
  "event_type": "tool_selected",
  "tool": "calculator",
  "arguments": {
    "a": 123,
    "b": 456,
    "operation": "multiply"
  }
}
```

# 4）给每个 Tool 记录耗时

修改：

```
def execute_tool(name, arguments, trace):
    start = time.perf_counter()

    trace.log(
        "tool_start",
        tool=name,
        arguments=arguments,
    )

    try:
        result = ...

        latency_ms = round(
            (time.perf_counter() - start) * 1000,
            2,
        )

        trace.log(
            "tool_end",
            tool=name,
            success=True,
            latency_ms=latency_ms,
        )

        return result

    except Exception as error:
        latency_ms = round(
            (time.perf_counter() - start) * 1000,
            2,
        )

        trace.log(
            "tool_end",
            tool=name,
            success=False,
            latency_ms=latency_ms,
            error=str(error),
        )

        raise
```

# 6）实现三个核心指标

新建：

```
# evaluator.py
```

至少计算：

### ① Tool Selection Accuracy

```
正确选择工具 / 总案例数
```

例如：

```
7 / 8 = 87.5%
```

------

### ② Tool Execution Success Rate

```
成功执行 / 应执行的 tool calls
```

例如：

```
9 / 10 = 90%
```

------

### ③ Task Success Rate

这个最重要。

最终结果是否完成用户任务：

```
successful tasks / total tasks
```

不要把：

```
tool selection accuracy
```

误认为：

```
agent quality
```

因为：

```
选对工具
≠
工具执行正确
≠
最终答案正确
```

这正是今天要建立的工程思维。

### 面试题 2

**“Observability 和 Evaluation 有什么区别？”**

一句话：

> **Observability 解释“发生了什么”，Evaluation 判断“做得好不好”。**

例如：

```
Observability:
Agent 调用了 search_knowledge
耗时 1.2 秒
返回 3 个 chunks
随后 LLM 生成答案

Evaluation:
这个答案到底对不对？
```

Hugging Face 当前 Agent Observability 材料也明确区分了两者：observability 关注运行过程的 signals，而 evaluation 是基于这些数据和测试判断系统质量。[Hugging Face](https://huggingface.co/learn/agents-course/en/bonus-unit2/what-is-agent-observability-and-evaluation?utm_source=chatgpt.com)
